## 0. 执行摘要与使用规则

把内宇宙从参赛作品变成产品，不是再加一批页面，而是同时建立四件事：用户愿意反复使用的私人价值、可靠且可控的 AI 与数据系统、可以履责的大陆运营体系，以及真实成立的收入和获客模型。

建议首发定位：帮助处在人生变化中的成年人，把日常表达变成自己能理解、能纠正、能带走的长期记忆；在本人愿意时，通过有边界的共鸣体和慢信，连接能理解这一部分自己的真实的人。

用户已经确认“中国大陆优先”。简体中文、18 岁以上为本方案的默认产品范围；重点研究 22–35 岁、毕业入职／职业转换／异地生活变化的人群。这一细分、收费意愿和价格都尚未经过真实客户验证。18+ 定位不产生未成年人保护豁免。

### 0.1 三种完成状态，绝不混用

| 完成态 | 必须具备的证据 | 不能替代它的东西 |
|---|---|---|
| PRODUCT_READY：工程与体验成立 | 全部目标能力、数据权利、异常恢复、非作者体验验收 | 页面齐全、测试数量、漂亮录屏 |
| CN_RELEASE_READY：可以在大陆发布运营 | 适用许可／备案／评估程序、实际生产、渠道审核、值班与客服闭环 | “仅内测”、云厂商资质、供应商模型备案 |
| BUSINESS_VALIDATED：商业假设获得支持 | 成熟用户队列、真实付费和退款、单位经济、可重复获客 | 注册人数、意向问卷、融资材料、算法名称 |

执行全部工作包，可以验收愿景中的产品能力与经营机制；不能保证用户购买、市场领先或投资到账。商业实验不成立时，完成实验的正确结果可能是收窄、重定位或停止扩量，不能伪造商业成功来关闭任务。

### 0.2 权威、历史与变更边界

1. 本轮明确的大陆商业化方向优先于旧文件中的新加坡首发、课堂公网隧道优先和不计合理推理成本的展示策略。旧 [目标](../../goal-objective.md)、[对齐索引](../../对齐文档/README.md)、08–12、16、24、25 中的创新意图继续保留；市场、成本、发布和运营冲突按本文裁决。
2. [旧验收账本](../goal/complete-product-acceptance.yml)、[旧状态](../goal/closure-campaign-state.yml)保留历史事实，不把旧 PASS 改写为大陆生产 PASS。CP-01 建立商业台账和逐项迁移表。课堂 W3 证据不删除、不重复“从零实现”。
3. 本文创建的是计划，不执行购买云资源、提交监管材料、发布商店、收款、上传私密数据、修改远端权限或重写 Git 历史。实际执行这些动作时，需要相应主体和账户所有者的授权。
4. 所有数字标为“目标／假设”的均非当前成绩、行业平均或对外 SLA。法律适用由具备资质的专业人士及主管部门核定；渠道规则提审前再核验。
5. 工作包不是要求重做已存在功能。先定位实现和测试，补差距；没有增益证据不更换框架，不按实体拆微服务，不用代码行数衡量成熟度。

## 2. 市场定位、用户价值与竞争策略

### 2.1 三项可证伪的核心假设

| 假设 | 研究问题 | 失败后的动作 |
|---|---|---|
| H1 私密价值独立成立 | 没有任何陌生人时，用户是否仍主动回来整理生活？ | 收窄具体场景；不靠假消息、强制分享或签到制造留存 |
| H2 长期理解有增量 | 相比用户已有通用 AI／日记工具，少重讲背景、理解变化是否有明显价值？ | 修记忆和反馈闭环；双核不增益则简化生产配置 |
| H3 授权共鸣改善真人连接 | 试聊一个获准侧面后，双方是否更愿意、有内容地交流且压力更低？ | 保留单人产品；暂停扩张社交供给，重新设计撮合 |

首发重点是“下班后 5–10 分钟理清一件事”和“周末 10 分钟看懂一周变化”，不是同时抢占聊天、心理治疗、约会、直播和效率工具所有市场。临床诊疗、色情陪伴、未成年亲密角色、婚恋结果保证、雇佣／保险／信贷人格评分均不在本轮范围。

### 2.2 对标的是具体任务，不是宣传口号

以下为 2026-09-05 官方资料研究，未完成同设备产品实测；官方能力描述不构成独立效果证据。

| 对标 | 已公开的能力与启发 | 内宇宙需要争取并实测的优势 |
|---|---|---|
| [Soul](https://www.soulapp.cn/en) | 兴趣／个性发现、广场、语音群聊、AI 社交与陪伴；“AI+社交”并不独有 | 只分享一个获准侧面，降低首联压力，改善双方愿意继续的比例 |
| [Slowly](https://slowly.app/) | 延时长信、语言／兴趣发现、昵称和头像；等待本身应清晰可预期 | 节律和收件容量可协商，减少无意义等待与被催促感 |
| [豆包实时语音官方资料](https://www.volcengine.com/docs/6561/162929?lang=en) | 自然语音、打断与表达体验是对标方向；模型指标不是整款产品指标 | 中文真实设备上的对话—记忆沉淀—后续回访整条链路 |
| [ChatGPT Memory](https://help.openai.com/en/articles/8590148-memory-faq) | 已有记忆摘要、纠正、来源解释、Temporary Chat；旧文档“一次性对话”判断过时 | 撤回对画像、向量、共鸣体、任务的完整影响；长期变化可解释 |
| [Replika](https://help.replika.com/hc/en-us/articles/360058852132-Is-Replika-sentient) | 连续陪伴与明确非真人、非有意识主体、非专业医疗人员的边界可以并存 | 有温度、有连续性，同时尊重退出、现实关系与用户主体性 |

三项领先主张只在证据成立后使用：①一个月后仍优先采用用户已经纠正的事实；②用户能看懂并撤回某个主题的全部可控派生影响；③授权侧面引发更高质量、低压力的双向真人往来。不得对外宣传“全面超过所有顶级产品”。

CP-04 的实验分成两条：回应盲评使用匿名输出、相同信息预算和随机顺序；完整产品体验采用交叉平衡顺序、相同任务与合理学习时间。记录地区、版本、套餐、设备、网络和日期。竞品没有某功能记“不适用”，不能记零分制造优势。不得为对标而把大陆真实私密对话发送到未经批准的境外服务。

### 2.3 可以积累的优势

长期中文理解与纠错评测资产、可验证的授权运行系统、用户可迁移的个人记忆质量、真实且边界可靠的社交供给、可履责的运营体系共同构成候选壁垒。RAG、双核、Kubernetes、通用模型名称不是独立壁垒。用户私密数据也不是可自由训练、出售或交给投资人的公司资产。

## 3. 产品全貌与必须兑现的体验合同

### 3.1 五个空间，一条逐渐展开的主线

| 空间 | 第一任务 | 次级能力与入口原则 |
|---|---|---|
| 今天／Aurora | 说清此刻的一件事 | 倾听偏好、文字／语音、预约、可选微行动；第一屏不强迫测评 |
| 内宇宙 | 看懂生活的变化 | 星空与等价列表、来源、时间线、日记／今日记录、周报、待办、心声、信念与思维整理；按任务分层，不纵向堆满模块 |
| 共鸣 | 选择可分享的侧面与愿意遇见的人 | 共鸣体工作台、沙盒、授权预览、目录／匹配、解释／反馈；社交默认未开启 |

| J11 | 不想继续→静默退出／拉黑→举报／申诉；好友／群组／推荐／推送一致执行 | 举报≤3步；不再推荐和接触；不向发送方细分泄露“拒绝／屏蔽”；读回执按收件方选择 |
| J12 | 购买／扣款成功但客户端超时→恢复权益→取消／退款→导出／注销 | 验签、重复／乱序回调、对账、换设备均通过；不重复收费；数据权利无付费墙 |

以上阈值为先验工程／研究目标，CP-04 在看结果前冻结样本和评分口径。关键旅程还必须覆盖 loading、empty、partial、offline、timeout、error、retry、expired、permission-denied、long-content、removed、account-frozen。按钮禁用原因可读，失败保留输入，成功后才关闭弹窗；不能用统一 toast 替代状态设计。

无障碍目标为 WCAG 2.2 AA：键盘／焦点、读屏、文本缩放、减少动态效果、对比度和错误识别一起验证。产品触控设计采用通常不小于 48×48 CSS px 的可点击区域；这不是把 WCAG AA 的 24×24 最低目标尺寸条款误写成 48px 法规。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)

## 4. 成功如何衡量：三项主指标，两项不可抵消的守门指标

本节采用“结果—驱动—守门”设计。候选集曾包括时长、DAU、消息数、生成记忆数、发信数、付费额、用户确认价值和长期留存。前五项易被刷量、强迫互动和多生成改善，保留作诊断，不作为北极星。

### 4.1 指标字典

### 4.2 目标冻结与商业实验

没有当前客户数据，不直接声称某个D7／D30或LTV数字是行业标准。先执行30次问题访谈（三细分各10人、至少半数非熟人）、15人可用性、60–100人至少35日研究（完整覆盖第28–34日窗口），再按方差和实际成本冻结下一批目标。涉及对公众提供服务前必须通过相应法律门，不以“邀请制”绕开。

暂定内部决策带：D30窗口价值留存低于15%且两次核心改版无改善，暂停扩量并重访需求；15%–25%继续限定范围实验；达到25%以上也只进入进一步验证，不自动等于PMF。此分带是预算管理假设，需在首批入组前由负责人签字，之后不得追着结果移动门槛。付费和安全若不成立，即使留存达标仍不得扩量。

比较实验以用户或社交供给单元随机化，避免双边社交互相污染；预注册主终点、最小有意义差异、停止条件和统计方法。样本不足报告探索结果和区间，不宣称显著领先。无泄露样本报告 0/N；近似独立二项试验可附 95% 上界约 3/N，相关轨迹按用户聚类估计，不宣称总体零风险。

## 6. 商业模式、获客、预算和投资准备

### 6.1 收费原则与产品包装

免费层提供完整的首次价值、合理文字额度、基本回看和最小社交体验；隐私设置、纠正、导出、删除、拉黑举报、取消与安全资源永不锁在付费墙后。付费增加透明的计算／语音额度、长周期复盘、私人探索工具和声音／视觉个性化。不出售“更爱你”、收件人回应、突破他人边界、心理弱点差别定价。

先测试一个主会员，不同时上线复杂积分、商城、创作者分成和企业套餐。29／49／79元每月仅为可研究价格点，不是已批准价格；支付前明确渠道价格、周期、税费、额度和到期行为。高风险会话不突然弹“续费才能继续被关心”；普通配额耗尽时保留草稿，明确剩余能力和恢复时间。

### 6.2 单位经济的统一算法

每任务成本 = 输入token／百万×输入单价 + 输出token／百万×输出单价 + ASR分钟费 + TTS字数或时长费 + embedding／审核费 + 重试／失败调用费。按供应商真实账单核对模型ID、缓存价、批处理价和币种，不能把所有 stage 当一次调用。

月净服务收入 R = 不含税实收 − 退款 − 支付与商店费用；可变直接成本 C 包括所有免费和付费用户的模型／语音、按量云、审核与客服；贡献利润 = R−C。固定基础云、研发、行政、法务和市场费用另计，不能把正贡献率称净盈利。

下面是用于检验算法的假设情景，绝非供应商报价或预测：月有效付费用户1000人，名义月价49元，暂不展开税项，退款3%，渠道／支付综合扣除取退款后金额的15%，免费活跃用户9000人。每付费用户直接用量成本12元，每免费活跃用户1元。

    R = 1000 × 49 × 0.97 × 0.85 = 40,400.50 元
    C = 1000 × 12 + 9000 × 1 = 21,000 元
    贡献利润 = 19,400.50 元；贡献率约 48.02%

若固定月运营支出为15万元，且此单位经济及免费／付费比例不变，静态平衡约需7732名付费用户；真实增长成本、税务、渠道结构和非线性容量可能显著改变结果。月价低／语音重／审核昂贵的悲观情景必须一起算。CP-47 使用真实合同替换假设，再决定额度和预算。

18个月现金计划按月列：期初现金、付费人数、实收、退款、各类成本、薪酬社保、外包、法务测评、获客、税务、资本性支出、期末现金；低／基准／高三情景。融资金额从下一组可证实里程碑所需现金倒推，不能从想要的估值倒推虚假收入。LTV 数据不成熟时仅报观察期累计贡献及情景区间。

### 6.3 冷启动与获客实验

1. 单人产品先成立；真实种子用户按共同处境与可用节律组成20–40人的供给单元，至少两批独立观察。合成示例永久标 AI，不制造真人来信、在线人数或虚假热度。
2. 一周有限推荐，用户设置收件容量；不足时解释等待、允许调整范围。不能为了填满页面牺牲边界和相关性，也不购买冒充用户的水军。
3. 初期内容渠道实验：小红书／公众号上的具体生活问题、成人兴趣社区、校友与职场转折社群。获得社区允许后开展招募；每个渠道记录触达→合规访问→激活→D30窗口价值留存→付费／退款；人工、补贴、创作者费用计入CAC。
4. 分享默认是用户选择的去身份卡片，先预览；不得自动把原始倾诉转为营销案例。推荐邀请不上传通讯录、不自动群发，不以分享换数据权利。
5. 每轮增长只改变少量变量，预设预算上限和退出条件。连续两批成熟队列、可承受的贡献经济和真实审核容量同时成立，才扩大投放。

### 6.4 投资人应看到的公司，而不是项目演示

数据室分层授权：公司／股权／IP、用户研究、产品与竞品证据、队列留存、订单与退款、单位经济／现金计划、合规／供应商合同、架构／安全／事故、团队能力与资金里程碑。附未关闭事项、失败样本、研究分母和日期。不得提供 P0 私密对话或可重新识别的人格数据；导师、评委、投资人均使用授权脱敏或明确合成演示账户。

路演用“问题→产品价值→为何现在→市场与可达范围→竞争证据→商业模式→团队→财务→融资用途→愿景”；该结构参考投资机构公开框架，不构成融资保证。[Sequoia商业计划框架](https://sequoiacap.com/article/writing-a-business-plan)

## 7. 工程与数据架构决策

### 7.1 保留现有主干，新增大陆商业环境

延续模块化单体及当前同一不可变镜像的api／worker／scheduler／migration角色。独立AI与事件worker是目标职责隔离，不是本轮已证实现状；CP-38依据吞吐与安全需要进一步分池／分role，并验证独立伸缩。PostgreSQL是事实源，Redis放会话／限流／短状态／租约。P0原始交互→P1私人派生→P2授权共鸣体→P3人际交流的历史分层继续有效，但每一层仍可能含个人信息，P2/P3不是“天然匿名”。

环境分离为 local、CI临时环境、staging-cn、commercial-cn；课堂／academy／commercial-sg独立保留。不同生产与测试环境使用不同账户或项目、网络、数据库、密钥和模型额度；不得将真实生产数据复制到普通开发者电脑。公网隧道、固定demo账号、H2和Mock不可进入commercial-cn。

### 7.2 主云选择与上线拓扑

先开展一周有预算上限的兼容性 PoC，候选为阿里云 ACK 或腾讯云 TKE；优先评估一套主云，不并行建设两个完整生产栈。检查实际账户区域可用性、托管 PG 的 pgvector 版本／TLS／PITR、Redis语义、K8s入口SSE、密钥管理、境内模型／审核、三运营商延迟和真实月成本，再以 ADR 选择。购买前由所有者确认报价和预算。[ACK区域说明](https://www.alibabacloud.com/help/en/ack/product-overview/supported-regions)

以 ACK 候选说明组件映射：VPC与私网节点、ALB/WAF与TLS入口、托管RDS PostgreSQL、Redis兼容服务、OSS、ACR、KMS／Secret、国内日志／OTel接收端；品牌可替换，验收合同不可省略。至少两可用区承载无状态生产工作负载，数据采用经演练的高可用与境内跨区域备份。备份在不同故障域和受限账户可取回，不能只放集群PVC。

NetworkPolicy是否执行要依CNI模式实测。ACK Terway有相应条件和限制，不得把“YAML渲染成功”当网络隔离；标准策略对域名控制不足时增加受控出站代理、DNS治理和供应商白名单。[ACK网络策略官方说明](https://www.alibabacloud.com/help/en/ack/ack-managed-and-ack-dedicated/user-guide/use-network-policies)

生产运维入口不直接公开，使用企业身份MFA、短期凭据、审批与审计；迁移角色独立授权，不让API持有DDL权限。CDN只缓存公开静态资产，私人API、SSE、导出和录音使用禁止共享缓存、短有效链接与权限校验。

### 7.3 不可破坏的系统合同

- 所有读取、派生、检索、模型调用和外发同时核验 owner、purpose、consent_version、policy_version、删除状态；检查发生在实际使用时，而不只在任务入队时。
- 模型网关涵盖 fast／planner／speaker／critic、embedding、ASR、TTS、moderation、失败回退和后台任务；Provider的品牌、账号区域、端点、处理位置和合同分别登记。未知路由拒绝，不偷偷跨境或回到Mock。
- outbox/inbox采用至少一次投递＋业务幂等实现有效一次领域副作用；外部模型计费、推送服务、支付网络不能笼统宣称全局exactly-once。幂等键、fencing、死信、回放及余额核对各司其职。
- 修正和撤回使旧派生物失效；新任务晚到也不能复活它。删除先阻断在线使用，再完成物理清理／备份生命周期；法定留存有独立用途和期限，不继续用于个性化。
- API逐域纳入版本化OpenAPI、类型化错误、游标分页、ETag／并发更新、Idempotency-Key；不以未经版本化的内部字段作为客户端产品协议。
- 发布绑定镜像digest、前端bundle、schema兼容区间、提示／模型／技能／安全策略／功能开关版本。模型升级是产品发布；不能静默改变记忆和人格。
- expand-contract在共享真实PG上验N/N-1；保留旧列直到旧应用退场且回滚窗结束。应用回滚不等于破坏性数据库down migration。
- 保留用户可见解释摘要、选择的证据与规则，不展示或承诺暴露模型原始隐藏思维链。“心声”是可选生成表达，不能宣传为读取AI真实意识。

### A. 事实、用户与评测

#### CP-01 权威迁移与真实能力台账

负责人：集成负责人；阶段S0；依赖：无；愿景V01、V16、V19。

- 执行：冻结本地／远端SHA与脏改；逐项映射旧69条验收和5个人工门到新商业要求；标保留、重验、被大陆替代或明确范围外。建立商业台账、架构决策、未决问题及证据索引；更新旧入口的商业指向但保留历史。

### 10.3 并行开发边界

设置三条实现轨：①用户体验／客户端；②AI／记忆／社交；③生产／合规工程。集成者独占迁移编号、共享API类型、全局文案字典、生成bundle、账本和发布manifest。金融／身份／授权共享契约先评审再并行；两个Agent不同时改同一契约或同一工作树的公共生成物。

工作包依赖是验收依赖，不阻止先用固定接口／合成数据做实现；替身不能关闭真实集成门。每周一次跨轨串联，阶段边界跑全量与独立验证。进度报告必须同时给完成、失败、跳过、外部门和下一步，不能只报百分比。

### 10.4 故障与扩量停止规则

- 立即停相关公开能力：未经授权读取／外发、严重危机处置失误、未成年亲密角色暴露、实质重复扣款、被撤回数据复活、未知境外处理路径。
- 停发布／扩量、保留安全服务：错误预算快速耗尽，权利请求／审核严重积压，单位成本突破批准预算，商店／监管材料过期或关键值班无人接管。
- 暂停产品方向而非改分母：两轮修正后私人价值仍低、社交增加压力、付费不覆盖可变成本、渠道无法产生成熟价值留存。由CP-64做经营决策。
- 不可回退的底线：安全资源、必要投诉／申诉、账户与财务事实、数据权利、已生效用户纠正。任何降级不能把这些当节约成本的开关。
