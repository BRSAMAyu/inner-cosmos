# Inner Cosmos 最终打磨与短时展示能力审计

> 审计日期：2026-07-26
>
> 事实基线：`codex/english-demo-i18n` / `11ff436`
>
> 文档性质：最终收敛审计与执行建议，不替代 `goal-objective.md`、对齐文档 24/25、验收账本或 Demo Runbook

## 1. 结论

Inner Cosmos 现在最不需要的是推翻重建。

项目已经有相当完整的产品和工程骨架：五空间 React 产品、真实 Aurora runtime、可追溯记忆与画像、共鸣体编译与沙盒、匹配、慢信和真人社交、PostgreSQL/pgvector、Redis、可靠事件、多运行角色、Android/PWA，以及已经真实验证的 Kubernetes 故障恢复、KEDA、OpenTelemetry、Argo Rollouts 和 Kyverno。把这些再换一套框架、拆成更多服务或堆更多云原生组件，短期只会稀释已经形成的优势。

最后阶段真正缺少的是四件事：

1. **把真实技术即时转化为用户能看到的因果反馈。** 用户说“记住”“提醒我”、写日记、结束对话、校准共鸣体后，相关界面和解释必须立即更新，不能要求刷新或让用户猜后台是否真的做了事。
2. **把“真实 LLM”变成不可误判的演示硬门。** 不能只看配置中的 Provider 名称；必须证明当次调用成功、没有 Mock、planner/speaker 没有 fallback，并在凭据或网络失效时明确失败。
3. **把单人纵向闭环转化为 30 人现场可完成的群体体验。** 不是只压一个接口，而是确保每个人能注册、获得不同的 Aurora 体验、形成最小共鸣体、找到人、发出真实连接，而且没有人落单。
4. **把大量工程证据压缩成 5 分钟产品体验和 7 分钟云原生证明。** 导师不应先听架构名词，而应先看到体验差异，再看到 Kubernetes 为什么保护这种体验。

因此，最终策略应是：

> **冻结横向扩张，集中关闭可感知反馈、真实 Provider、目标 Windows 并发、非作者可用性和演示叙事五个收口门。**

## 2. 审计方法与事实等级

本文只采用以下四类事实：

| 标记 | 含义 | 可以怎样表述 |
|---|---|---|
| **已验证** | 有当前代码、自动测试、浏览器/设备运行或留存 evidence | 可以说“已经实现并在指定环境验证” |
| **已实现，待目标环境复验** | 代码和局部测试成立，但 Windows、公网、真机或真实 Provider 尚未在当前提交复验 | 可以说“已有能力，正式 Demo 前需复验” |
| **真实缺口** | 当前行为、权威账本或运行观察明确显示未闭合 | 应列入收敛工作 |
| **外部门禁** | 必须由有权限的人、真实设备、账户、专家或真实用户完成 | 不能由代码或 Agent 冒充 PASS |

特别说明：

- 旧 evidence 对它记录的提交和环境仍然有效；本文不会因为当前凭据失效就否定以前真实成功过的 Provider 运行。
- 同样，旧 evidence 不能自动证明当前提交、当前密钥、当前 Windows 和本次公网地址仍然可用。
- 用户自己输入的中文、历史日记和共鸣体内容不是国际化缺陷；系统生成文案在英文模式仍为中文才是缺陷。
- H2/Mock 仍然是合理的离线开发与回归工具；它不能替代课堂真实 LLM、公网设备或 PostgreSQL/Redis 的验收。

## 3. 已经做对、应该冻结和复用的能力

### 3.1 产品骨架

以下能力不是本轮需要重做的问题：

- 五空间信息架构已经形成：Aurora、Cosmos、Resonance、Connect、Me。
- 长页面已经通过二级导航拆开；功能不再全部纵向堆叠。
- 登录、注册和普通真实用户不会看到三个课堂故事切换器。
- 三个长期故事不是多人共用同一账户写数据，而是按浏览器 Session 创建独立 `SANDBOX` 副本；沙盒共鸣体默认私有。
- 普通注册用户拥有真实独立数据，可以发现其他真实用户、添加好友、加入群组、发布共鸣体和发送慢信。
- React AppShell 已经是课堂主入口；旧静态页不应在最后阶段重新成为主路径。

这已经解决了“多人同时登录 demo 账户互相污染”的核心设计问题。剩余的只是沙盒 TTL 和多 Pod 分布式创建锁，它们不是 Windows 单节点课堂 Demo 的前置条件。

### 3.2 Aurora 与信息流

以下基础已经存在，应在其上打磨：

- Aurora 有 foreground acknowledgement、planner、speaker、bounded critic 和 adaptive runtime。
- SSE 支持多气泡、停止、打断、恢复和 durable timeline。
- WakeIntent 是持久化计划，不是浏览器临时时钟；具有时区、静默时段、取消、延期和恢复路径。
- 当前提交增加了确认门控的自然语言动作：记忆、提醒和少量设置。模型文字不直接获得写权限。
- 新用户昵称和轻量校准已经进入首次上下文，两个新用户不应收到完全相同的开场。
- 日记、对话沉淀、记忆检索、画像、共鸣体和匹配已有数据链路，不是互相孤立的静态页面。
- 共鸣体已有授权记忆、Genome、边界、私密沙盒、自然语言校准、发布、撤回和版本路径。

确认门控应保留。最后打磨不是让 LLM 随意改数据库，而是让 Aurora 在可解释、可撤回、用户明确同意的边界内更自然地使用现有工具。

### 3.3 安全、数据和并发基础

以下工程基础已经有明确证据，不应因为最后冲刺而弱化：

- owner scope、AI 数据边界、慢信/记忆/共鸣体状态并发、客户端 SSE 韧性已经通过专项审计和回归测试。
- PostgreSQL + Flyway 是生产事实源，pgvector 承担语义检索；Redis 承担共享会话、限流、幂等、流和租约。
- 事务 outbox、幂等消费、条件更新、撤回传播和恢复机制已经存在。
- 控制器到服务到数据层的边界已经由 ArchUnit 固化；没有必要为了课程展示迁移到 Spring Modulith 或拆微服务。
- 当前树密钥扫描使用环境变量/外部注入，代码中没有把真实 Provider key 作为默认配置提交。

### 3.4 UI、国际化和跨端基础

当前提交前后的修正已经覆盖一批真实问题：

- 英文五空间导航、Cosmos 二级导航、记忆系统生成标题、Aurora Self 基线等已补充本地化。
- 浅色模式的登录、Aurora 对话框和残留夜间 literal color 已做收敛。
- 时间主题预览已支持手动调节，不再只能等待现实时间变化。
- 语音和语言选择已压缩，避免大量平铺占据首屏。
- Cosmos 时间视图对“同一时刻生成多个节点”增加了碰撞展开，避免全部堆在最右侧。
- PWA 生产资源已使用哈希文件名，并改进更新提示和自动更新路径。
- 五空间、日/夜、中/英的 axe-core 矩阵已有 20 组扫描证据；性能 evidence 中 TTFB、FCP、LCP、CLS 和交互时间均处于适合课堂演示的范围。

这些能力应该通过目标设备复验，不应再次更换视觉体系或重写路由。

### 3.5 云原生能力

W3 已完成并应冻结。当前已有真实证据：

- 普通 Pod 删除和 JVM SIGKILL 后，Aurora turn 能排空或被明确标为 `INTERRUPTED`，不会无限悬挂。
- KEDA 根据 outbox 数量和最老任务年龄完成 `1 → 6 → 3 → 1`，并证明租约重领和 inbox 无重复副作用。
- OpenTelemetry/Jaeger 贯通 API、Provider、检索、outbox、worker、记忆、画像和 WakeIntent，同时过滤正文和稳定用户标识。
- Argo Rollouts 已证明好版本推进和坏版本自动 abort。
- Kyverno 已真实拒绝 root、无资源限制和 `latest` 镜像，并验证 kill switch。
- Academy EKS 已有 Gateway、角色拆分、HPA、Pod 恢复等真实教学环境证据。

最后阶段只需要把这些证据编成可稳定讲述的 60–90 秒片段，不需要再安装更多插件。

## 4. 真实剩余缺口

### 4.1 P0：不关闭就不能把课堂 Demo 称为“真实完整体验”

#### P0-1：当前真实 Provider 凭据和演示就绪状态必须重新建立

本轮 Mac 实验中，被实际调用的 DeepSeek 和 MiMo 凭据均返回过 `401`。结构化 AI 层仍会返回确定性业务 fallback；这对产品韧性有价值，但不能被当作“真实 LLM 成功”。

需要完成：

1. 撤销并轮换曾在聊天中暴露的所有 Provider key，由操作者在外部 Secret/本地忽略文件中注入。
2. Windows `run-public-demo.ps1` 启动时先做真实 Provider 探针，再启动正式验证。
3. Demo 就绪不能只检查 `provider != mock`，还必须同时检查：
   - `apiKeyConfigured == true`
   - `fallbackAllowed == false`
   - 实际调用无 `401/403/429/timeout`
   - `agentLoop.plannerFallbackUsed == false`
   - `agentLoop.speakerFallbackUsed == false`
   - 关键结构化产物没有 `FALLBACK_USED`
4. 任一条件失败时输出 `PUBLIC_DEMO_NOT_READY`，而不是让正常 UI 看起来像真实模型已经成功。

不建议删除所有业务 fallback。正确做法是：

> **产品运行可以优雅降级；真实 LLM 的课堂验收不能把降级算作成功。**

#### P0-2：确认动作后的界面必须立即反映真实结果

当前“记住这件事”在确认后能真正写入 MemoryCard，“提醒我”能真正写入 WakeIntent；但本轮浏览器实测中，新记忆需要刷新后才在 Today/Cosmos 出现。代码里对“结束对话并沉淀”有主动刷新，对自然语言动作执行没有同等的跨域状态失效。

这会直接破坏“技术无感”的体验：用户已经收到“已记住”，却看不到任何变化。

需要完成一个统一的 `product-state-changed` 路径：

| 动作结果 | 立即更新 |
|---|---|
| `REMEMBER` | Today 记忆数量、MemoryCard 列表、星空、来源操作记录 |
| `REMINDER` | Aurora Returns/WakeIntent 列表、原生本地通知计划 |
| `PROFILE_SETTING` | Me/Profile 当前值和相关控件 |
| 日记沉淀 | Cosmos 时间轴、记忆、画像待确认项 |
| 共鸣体校准/重编译 | readiness、Genome 版本、沙盒预览、匹配索引状态 |
| 发布/撤回 | 公共目录、匹配候选、访客会话可用性 |

验收不能只查数据库；要在不刷新页面的情况下看到相应区域更新，并能点开来源。

#### P0-3：动作轮次的对话编排还需变得更自然

Web 在发送每条消息前会先调用 foreground acknowledgement，然后 authoritative stream 才执行自然语言动作拦截。因此“Remember that…”或“Confirm”可能先出现一条泛化的快速回应，再出现确定性的动作提案/执行回执。

安全没有问题，但体验可能显得像两个系统在说话。

应做的最小调整：

- 在 foreground 路径也执行只读的高精度 action classification；命中明确动作/确认词时，不生成普通情绪 acknowledgement。
- 动作提案仍由 authoritative stream 持久化，foreground 不能写数据。
- “Confirm”应直接形成一句自然回执和一个可打开的结果卡，不再触发无关的关怀式句子。
- 普通聊天完全保留现有双核节奏。

不要把动作解析改成“LLM 说什么就执行什么”。只有当前三类 allow-list 在证据充分后再逐类扩展。

#### P0-4：必须在目标 Windows 上完成两层 30 人验收

仓库已经有 `scripts/demo/test-30-user-burst.ps1`，但当前还不能说“30 人全功能通过”：

- 该脚本尚未在本轮 Mac 执行；目标入口本来就是 Windows PowerShell 7。
- 单次脚本覆盖注册、轻量校准、一轮真实 Aurora、30 人发现和环形好友连接。
- 它尚未覆盖 5–8 分钟多轮聊天、结束沉淀、embedding、共鸣体编译/发布、匹配和慢信。

正式门禁分两层：

**第一层：短 burst**

- 30 人并发注册和校准；
- 每人一轮真实 Aurora；
- Mock/fallback/401/429/非预期 5xx 均为 0；
- 每人发现其余 29 人并进入环形连接；
- 报告成功清理测试账号；
- 输出 `CLASSROOM_BURST_PASS`。

**第二层：完整课堂彩排**

- 至少两轮相同配置；
- 30 人中每人完成多轮交流或最小快速轨迹；
- 记忆/画像物化，embedding backlog 清空；
- 每人拥有可用私密共鸣体并能选择发布；
- 每人至少获得一个安全候选或明确的“班级兜底相遇”；
- 至少完成一组真实跨用户共鸣体访问和慢信；
- 0 跨账号数据、0 重复副作用、0 丢信；
- 留存 TTFT/完整回复 p50/p95/p99、Provider 429、AI queue、DB pool、outbox oldest age、embedding remaining、CPU/内存和隧道错误。

只有第二层完成，才能说“30 人真实 Provider 全功能课堂轨迹已通过”。

#### P0-5：物理 Android + 蜂窝网络必须完成一次真实冒烟

当前已有 Windows、Quick Tunnel 和 Android 模拟器 evidence，但最终课堂仍缺：

- 至少一台真实 Android 手机；
- 不连接演示电脑局域网，使用蜂窝网络；
- 打开 Landing、下载当次 APK、旁加载、注册、登录；
- 完成一轮真实 Aurora；
- 杀进程再打开，确认 Session/草稿/当前状态符合预期。

这也是对“不同局域网能否访问”的最终回答：技术设计可行，依赖公网 HTTPS 隧道；真正的完成证据必须来自蜂窝网络。Quick Tunnel 重启后旧 URL 和旧 APK 均可能失效，这是设计边界，不是应用 bug。

#### P0-6：必须做一次非作者、无口头指导的可用性验收

当前 `FINAL-USABILITY` 仍是 `UNASSESSED`。组员不知道功能，正说明“功能存在”尚未转化成“功能可被发现”。

建议用 3–5 名非作者参与者，给出目标而不是步骤：

1. “让 Aurora 更了解你，并让她以后记住一件事。”
2. “建立一个你愿意让别人访问的共鸣体，但不要泄露原始日记。”
3. “找到现场另一个人，访问其共鸣体并发一封慢信。”
4. “解释 Aurora 为什么知道某件事，并纠正一处不准确理解。”

记录：

- 完成率；
- 首次犹豫点；
- 误点/返回次数；
- 是否需要作者解释；
- 参与者用一句话描述产品独特价值；
- 他们是否知道数据是否已保存、发布或撤回。

优先修复三人以上重复遇到的问题，不根据作者个人审美继续大面积改 UI。

### 4.2 P1：最能把“工程很强”转化成“体验明显不同”的打磨

#### P1-1：让信息流有可见、但不打扰的因果链

用户不需要看到技术名词，但需要知道系统真的在工作。建议统一使用四种轻量反馈：

1. **即时回执**：例如“已记住，只有你和 Aurora 可以使用”。
2. **来源入口**：例如“来自刚才这段对话 / 这篇日记”。
3. **后台进度**：例如“记忆已生成，语义索引正在完成；不影响你继续使用”。
4. **影响范围**：例如“这次纠正会让 1 个共鸣体进入待复核，公共访问已暂停”。

这套反馈应复用已有 receipt、operation、outbox 和 provenance 数据，不要新建第二套状态。

#### P1-2：把轻量校准压缩成 45–90 秒，并让第一句话立即不同

现有昵称、语气、主动程度、反思深度和当前关注点已经能进入上下文。最后需要验证：

- 用户可以跳过，不被问卷阻塞；
- 选择项不超过一屏，移动端不用长时间滚动；
- Aurora 的第一句话引用一个具体差异，不复述选择表；
- 两名用户互相对比时，话题、节奏或关注角度明显不同；
- Aurora 使用用户当前语言回复，而不是被 UI locale 永久锁死；
- 真实 Provider 失败时，界面明确提示“个性化开场暂不可用”，不拿本地模板冒充模型能力。

不要继续增加人格测试。轻量校准只负责给 Aurora 一个自然的第一把手，真正的了解来自后续对话和可纠正记忆。

#### P1-3：把“10 分钟共鸣体”做成有完成感的自然构建过程

当前技术上已有记忆选择、Genome、coverage、沙盒和自然语言反馈。体验还应收敛为：

1. Aurora 在对话中知道当前共鸣体覆盖度，而不是突然弹出表单。
2. 她只追问当前最缺、最有信息增益的一维，例如价值张力、表达方式或边界。
3. 用户讲一个具体故事后，coverage 立即变化。
4. 进入 Resonance 时，最新授权记忆已经被选中，但仍是私密草稿。
5. 用户先问自己的共鸣体一句话，直接说“这里不像我，因为……”。
6. 自然语言反馈形成新版本，并展示改了什么。
7. 发布必须由用户主动确认；不完整也可以保持私有，不能为了演示自动公开。

短时体验的关键不是伪造高完成度，而是让参与者看到：

> “Aurora 知道还缺什么 → 自然地问出来 → 新信息马上改变共鸣体 → 我能纠正它。”

#### P1-4：为 30 人设计“无人落单”的冷启动策略

匹配算法已有多策略、双向 block、MMR 和解释，但课堂冷启动还有运营层问题：

- 用户可能尚未发布共鸣体；
- embedding 尚未完成；
- 30 人的完成速度不同；
- 严格阈值下可能暂时没有候选。

建议按真实信号分层降级：

1. 先使用完成 embedding 的多目标匹配；
2. 等待期间用结构化兴趣/阶段/关系偏好产生明确标注的临时候选；
3. 若仍为空，使用课堂 cohort 的安全轮转配对；
4. 双向 block、隐私边界和“是否愿意被发现”永不降级；
5. UI 解释当前依据，不能把 cohort fallback 说成语义匹配。

目标不是让算法永远返回最高分，而是保证现场没有人因为系统冷启动而被留在空页面。

#### P1-5：补齐“当前语言”和“系统语言”的边界测试

当前英文残留已修正很多，但完整验收还应覆盖：

- 登录、注册、五空间、所有二级导航、日期选择器、空态、错误态、权限态；
- 记忆来源、画像基线、共鸣体边界、慢信状态、群组和 Admin；
- Android WebView、PWA 安装提示和系统通知；
- 英文模式加载旧中文种子时，已知系统默认标题可本地化；
- 用户自己写的中文正文保持原文；
- 清理旧 Demo volume 后重新生成英文课堂种子。

验收要以“系统生成 copy 零意外混语”为目标，不以全仓库 `rg` 不出现汉字为目标。

#### P1-6：完成剩余 UI 状态矩阵和真实设备视觉验收

已有设计系统和 axe 自动扫描，不应说“UI 没做”。尚未闭合的是明确的剩余矩阵：

- 390px 小屏；
- 投影仪宽屏；
- 浏览器 200% 字体；
- 键盘-only；
- reduced motion；
- Android TalkBack；
- loading、streaming、partial、offline、error、retry、expired、permission、long-copy；
- 时间星空在 3、10、30 个近时节点下的可读性；
- 浅色模式所有 modal、popover、date picker、voice picker 和登录组件。

建议建立固定截图集和允许差异阈值，避免靠肉眼每次重新巡查全站。

#### P1-7：把双核优势从“结构成立”补到“独立体验成立”

当前双核已经有真实 DeepSeek pairwise：修复后自动 lexical rubric 上 dual-kernel 为 `16/22`，single-pass 为 `12/22`。当前提交另有离线结构测试证明 planner → speaker → critic 的信息链，但它不证明语言质量。

剩余应是一次小而严格的盲评，不是继续堆 Agent：

- 相同 Provider、相同输入、随机顺序；
- 至少两名非作者；
- 预先固定 10–20 个场景；
- 评价具体性、情绪准确、关系感、行动价值、黏腻/模板感、是否复述用户；
- 记录所有失败分母；
- 目标不仅是平均胜出，还要找出“更差时为什么更差”。

如果未过门，不要删双核；优先修 planner/speaker 的信息压缩、复述和 critic 触发条件。

#### P1-8：做一个面向课堂的统一运行态面板

不需要新建复杂运维产品。现有 API、Prometheus 和 OTel 已有足够信号，只需整理一页：

- 当前 Provider、model、key configured、fallback allowed；
- 最近真实调用成功率、401/429/timeout；
- single/adaptive/dual 轮次和端到端延迟；
- API/AI executor queue/DB pool；
- outbox ready/oldest/dead；
- embedding remaining/失败；
- 在线用户和当前演示账号数量；
- 一条可打开的隐私安全 Trace。

这页既帮助演示，也能在现场 30 秒判断是 Provider、隧道、数据库还是 worker 出问题。

不要声称现有 Jaeger 已有一条
`Aurora → embedding → matching → slow letter` 的完整单 trace；当前真实链路只覆盖到已经埋点的角色和投影。

## 5. 5 分钟产品展示：把差异压缩成一条因果链

5 分钟只能证明即时能力，不能证明几个月的真实关系演化。正确做法是并行使用“独立长期沙盒”和“新注册用户”。

### 0:00–0:35：先展示长期结果，不让现场等待

- 导师进入一个独立故事沙盒。
- 快速看到几个月后的记忆星空、画像变化、共鸣体和慢信。
- 明确说明这是预置长期轨迹的独立副本，用来展示“长期使用后会长成什么样”，不是导师刚刚生成的。

### 0:35–1:15：新用户轻量校准

- 两名同学注册真实账号并填写昵称。
- 每人用 45 秒以内选择语气、主动程度、反思深度和当下关注。
- 同屏或口头对比 Aurora 主动开场，指出她们使用的语言、话题和节奏不同。

### 1:15–2:10：真实聊天 + 真实动作

- 用户说一件具体的当下压力或期待。
- Aurora 给出自然、非模板化的真实 LLM 回应。
- 用户说“Remember that…”或“提醒我明天……”，明确确认。
- 页面立即出现记忆星/提醒回执，并能打开来源。

这一段同时证明：真实模型、主动性、记忆、工具调用、确认边界和即时数据流。

### 2:10–3:05：从对话到共鸣体

- 结束会话或沉淀刚才内容。
- 展示最新记忆已经进入私密共鸣体草稿。
- Aurora 指出当前最缺的一维，用户用一句自然语言补充。
- coverage/版本立即变化，用户问自己的共鸣体一句话并校准“哪里不像我”。

### 3:05–4:20：从共鸣体到真人

- 用户主动发布共鸣体。
- 另一位用户通过解释型匹配或课堂 cohort fallback 发现它。
- 访问对方共鸣体，问一句授权范围内的问题。
- 写一封短慢信；对方在 Connect 看到真实状态。

### 4:20–5:00：一句话解释工程

- 打开运行态面板：真实 Provider、无 fallback、outbox/embedding 已完成、两位真实用户已连接。
- 收束：

> Aurora 不只是回复一段文字。她把对话转化成用户可纠正、可撤回的长期理解，再把被授权的部分编译成共鸣体，最后帮助真实的人找到低压力但有质量的连接。

## 6. 7 分钟云原生展示：解释为什么体验不会轻易断

产品段和云原生段是两个环境、一个叙事：

- Windows + Quick Tunnel 证明真实用户、真实 LLM 和真实社交。
- 预置 kind 展柜证明同一领域系统如何被 Kubernetes 保护。
- Academy EKS evidence 证明教学云环境可移植性。

推荐顺序：

1. **60 秒 Grafana/Jaeger**：展示 API/worker/scheduler、outbox 和一条隐私安全 trace。
2. **75 秒删除 API Pod**：普通删除即可；展示另一个副本继续服务和 turn 恢复。
3. **60 秒 KEDA**：使用预先准备的曲线/evidence 说明业务积压驱动 `1 → 6 → 3 → 1`。
4. **60 秒 Argo Rollouts**：展示坏版本自动 abort，强调当前依据是健康信号，不是完整 AI 语义质量。
5. **45 秒 Kyverno**：server-side dry-run 拒绝 root、无 limits 和 `latest`。
6. **60 秒环境边界**：Windows 不是 Kubernetes；kind AI 是 Mock 运行语义证据；Academy 静态 PV 不是商业多 AZ。
7. **60 秒总结**：云原生不是装饰，而是确保长期陪伴、异步记忆和真人连接在故障、积压和发布时保持连续。

课堂前必须预装并预热 kind 展柜。现场不临时安装 CRD、控制器或重建整个集群。

## 8. 课堂 Demo 的硬性 Go / No-Go 标准

### Go

只有同时满足下列条件才进入真实互动演示：

- Windows `postgres`、`redis`、`app` healthy；
- Quick Tunnel 存活，手机蜂窝网络可打开；
- 当次 APK 来自当次公网地址，SHA-256 记录一致；
- 至少一个新账号注册成功；
- 真实 Provider 探针成功，Mock/fallback 为 0；
- 一轮 Aurora、一次记忆沉淀、一次共鸣体发布/访问、一次慢信已冒烟；
- 30 人短 burst 至少一轮通过；
- kind 展柜已预热，Status 只读检查通过；
- 非作者至少一次走通主路径；
- 电脑接电、关闭休眠，准备本地 URL 和 evidence 兜底。

### No-Go 或降级

| 情况 | 处理 |
|---|---|
| Provider `401/403` | 不演示“真实 Aurora”；更换已轮换凭据并重跑，不切 Mock 冒充 |
| Provider `429/timeout` | 明示容量/网络失败，切长期故事沙盒；保留错误证据 |
| Quick Tunnel 断开 | 讲台改本机 URL，暂停台下互动 |
| 30 人 burst 未过 | 只邀请少量已彩排设备互动，不宣称 30 人容量 |
| 手机旁加载失败 | 使用浏览器 PWA；不发送旧 APK |
| kind 未 Ready | 不做现场 delete/patch，展示冻结 evidence |
| Jaeger 无 fresh trace | 展示已留存 trace 和当前限制 |

降级路线可以保证 presentation 完成，但不能改变能力声明。

这张表保留了完全体全部领域，同时明确哪些是课堂收口，避免因为 presentation 压力错误删除长期目标。

## 11. 明确不做

最后阶段不要做以下工作：

- 不重写为微服务，不为了“云原生感”把模块随意拆网络边界。
- 不迁移 GraphQL，不全量重做 API，不为了统一而破坏已验核心旅程。
- 不重新设计五空间，不再增加一个平行主导航。
- 不替换已经形成的暖色时间主题和视觉 token 系统。
- 不为了英文演示翻译用户自己写的中文内容。
- 不把所有 safe fallback 删除；只禁止它冒充真实 Provider 验收成功。
- 不让 LLM 获得无确认的任意数据库写权限。
- 不为 5 分钟现场伪造新用户的几个月历史。
- 不把 Windows 公网 Demo 描述为 Kubernetes。
- 不把 kind 的 Mock AI 描述为真实模型质量证据。
- 不继续安装 Cilium、Velero、Falco、Argo CD、Tempo 等新展柜，除非已有能力失效且它是唯一修复路径。
- 不在课堂现场临时安装 CRD、搭集群、轮换数据库或执行高风险故障。
- 不把 Android 构建成功等同于真机、蜂窝和当次公网 APK 可用。
- 不把一次 30 人接口脚本成功等同于两轮全功能容量通过。

## 12. 最终完成定义

本轮“优秀、拿得出手、可短时间展示”的完成，不等于商业完全体所有 G0–G9 已经 PASS。它应达到：

1. 5 分钟内，非作者能感受到不同用户的 Aurora 从第一句话开始就不同。
2. 用户说“记住/提醒”后，真实数据和界面立即联动，并能解释来源和权限。
3. 新用户在 10 分钟内能形成可对话、可自然语言校准的私密共鸣体。
4. 两名现场用户能真实发现、访问、写信和连接；30 人彩排证明不会大面积落单或打爆 Provider。
5. Demo 全程使用真实 LLM；失败被明确识别，不用 Mock 冒充。
6. 长期能力用独立沙盒诚实展示，现场即时能力用真实注册用户证明。
7. Windows 公网、真机蜂窝、非作者体验和两轮彩排均有当前提交的 evidence。
8. Kubernetes 段只展示已验证能力，并能准确说明每项实验证明了什么、没有证明什么。
9. README、Runbook、slides、machine cursor 和 acceptance ledger 对当前提交使用同一事实口径。
10. 所有剩余项都被明确放入发布/商业/人类门禁，而不是以“以后再说”隐藏。

达到这一状态时，Inner Cosmos 展示的就不再是“功能很多”，而是一条完整、可信、可感知的能力：

> **自然对话进入可纠正的长期理解；长期理解经用户授权形成高保真共鸣体；共鸣体帮助真实的人相遇；云原生系统保证这条信息流在并发、故障、积压和发布中仍然连续。**
