# Inner Cosmos Demo UX 阻塞项验收合同

> 目的：把 2026-07-27 组员反馈转成可观察、可快速复测的产品合同。本文不替代产品规格；
> 若与 `goal-objective.md`、`对齐文档/README.md` 或当前 Demo Runbook 冲突，以权威文档为准。

## 本轮原则

- 首屏只有一个主任务：和 Aurora 开始或继续对话。
- 解释文字不能替代可发现的交互；能由标题、状态、按钮和即时反馈说明的内容不再写成长段。
- “体验优先”只关闭重复声明、礼仪性边界话术和纯词面 `UNSUPPORTED` 死路；危机拦截、越权读取、
  屏蔽话题、联系方式脱敏和提示词泄漏防护不允许被开关关闭。
- 新用户引导采用“做一件事、看到一次结果、再去下一站”，不采用一次性功能说明书。

## 12 项可观察验收

| # | 体验合同 | 组员快速复测 |
|---|---|---|
| 1 | 进入“今天”后，Aurora 消息区和输入框占据首个视口主体；装饰球不再挤压会话高度。 | 1366×768 与手机尺寸各打开一次，不滚动即可看到模式、消息区和输入框。 |
| 2 | 首屏、共鸣广场和设置不出现“此刻的候选”“正在成为”等无行为含义的抽象标签。 | 不看说明文也能说清每个标题下可以做什么。 |
| 3 | 点击任一记忆星体立即出现详情抽屉；空星空明确告诉用户如何产生第一颗星。 | 点击星星、关闭抽屉、重新打开；三步都有可见反馈。 |
| 4 | 设置按账户、外观、数据、引导分区；声线可试听和保存；退出必须二次确认。 | 选择声线并试听，再点击退出并取消一次、确认一次。 |
| 5 | Demo 账号进入共鸣广场即可看到官方共鸣体，并能完成至少三轮自然对话。 | 清空浏览器状态后登录，不需要先自行创建共鸣体。 |
| 6 | Aurora 模式改变行为而非标签：整理拆层、追问只问一个关键问题、行动只给一个十分钟动作、关系不猜第三方动机。 | 用同一段困扰分别测试四种模式，盲看回复也能辨认模式。 |
| 7 | 球体是低干扰背景标识；夜晚有稀疏流星和星光，白天按时段改变光色且不影响可读性。 | 上午、黄昏、夜晚主题各看一次；文本对比度始终合格。 |
| 8 | 共鸣体身份只在首次进入会话时说明；恢复会话和后续回复不重复。 | 连续三轮对话并刷新恢复，不再看到重复声明。 |
| 9 | 默认体验优先模式不因普通寒暄或词面不重合而回复 `UNSUPPORTED`；关闭开关可恢复保守模式。 | 对官方共鸣体说“嗨，今晚怎么样”，应从授权人格自然回应。 |
| 10 | “Aurora 正在成为”不再占首屏；高级版本能力只在设置的折叠区域出现，并改用直白名称。 | 首屏无该模块；设置引导页可找到“记忆与回应方式”。 |
| 11 | 周报接口缺少可选数组或返回旧版 V2 结构时，页面显示可用部分而不是模块崩溃。 | 用缺少 `dailySnapshots` 的响应渲染，仍能看到周报摘要。 |
| 12 | 首次登录出现五步“第一次环游”；可跳过、可继续、完成后不重复弹出，设置里可以重新打开并直达核心功能。 | 新账号完整走一次，刷新后不再弹出，再从设置重新打开。 |

## 快速迭代顺序

1. 组员先走：今天对话 → 内宇宙星星 → 共鸣广场三轮对话 → 我的/声线/退出。
2. 每个失败只记录“操作、预期、实际、截图/控制台”，不要先猜原因。
3. 修复只跑对应组件或服务测试；一轮体验问题收敛后再统一跑全量。
